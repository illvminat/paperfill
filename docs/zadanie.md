# Задание: paperfill

Версия 1, 2026-09-19. Масштаб A. История изменений в конце файла.
Каждое утверждение о платформе — ссылка на `SOURCES.md`.

## 1. Назначение
Инструмент, который показывает заказчику форму поставки торгового бота для
Polymarket без единой реальной сделки: запись и реплей рыночных данных,
симуляция исполнения с комиссиями рынка, риск-контур, журнал решений,
отчёт метрик, панель. Целевые рынки — короткие крипторынки «Up or Down»
(5 и 15 минут): у них закрытие каждые 5 минут, полная история сделок и
одинаковая схема комиссий (`docs/measurements/2026-09-19-api-probe.md`).

## 2. Объём

### Обязательное для выпуска (v0.1)
| № | Функция | Задача пользователя | Критерий приёмки |
|---|---|---|---|
| M1 | Поиск рынков | Увидеть открытые рынки Up/Down по активу и длительности с их `feeSchedule`, мин. ордером и тиком | `paperfill discover --asset BTC --window 5m` печатает таблицу; поля берутся из ответа Gamma, не из констант; тест на разбор ответа из зафиксированного JSON |
| M2 | Запись данных | Записать стакан и сделки живого рынка по WebSocket в локальное хранилище | `paperfill record` пишет append-only файл событий с временем получения; обрыв соединения помечается событием `gap`, переподключение автоматическое; тест на разбор сообщений по `asyncapi.json` |
| M3 | Реплей истории | Получить полную историю сделок закрытого рынка и проиграть её как поток событий | `paperfill replay --condition <id>` проходит все страницы `/v2/trades`, уважает `Retry-After`; число сделок совпадает с суммой страниц; повторный запуск даёт тот же поток (детерминизм) |
| M4 | Симуляция исполнения | Выставлять бумажные лимитные ордера и получать исполнения так, как их дал бы рынок | Ордер проверяется на тик и мин. размер из данных рынка; исполнение против стакана уровень за уровнем (живая запись) или по пересечению ленты сделок (реплей); частичные исполнения; комиссия по `feeSchedule` рынка, только тейкер, округление до 5 знаков; тесты на таблицы примеров из `polymarket/fees.md` и на стакан из трёх уровней, посчитанный руками |
| M5 | Риск-контур | Не дать стратегии выйти за лимиты, остановить всё одним действием | Лимиты: капитал на рынок, общая экспозиция, дневной и общий убыток (circuit breaker), позиция на рынок; kill switch файлом и командой `paperfill kill`; пауза; тест на каждый лимит: нарушение → ордер отклонён с причиной в журнале |
| M6 | Стратегия-образец | Показать, как подключается стратегия, на примере двухстороннего котирования с наклоном | Интерфейс `Strategy` с одним методом на событие; образец котирует обе стороны 5/15-минутного рынка с настраиваемым наклоном по движению середины; в README: образец, не совет; тест на детерминизм решений |
| M7 | Журнал решений | Восстановить, почему был каждый ордер, отмена, исполнение и отказ | Append-only журнал с hash-цепочкой; каждая запись имеет причину; `paperfill journal verify` подтверждает целостность; тест: подмена одной записи ломает проверку |
| M8 | Отчёт метрик | Получить честные цифры прогона после комиссий | Число сделок, доля двухсторонних окон, доля исполнений, чистый P&L после комиссий, макс. просадка, win rate по корзинам уверенности, разбивка по рынкам; Markdown и JSON; отрицательные результаты выводятся так же, как положительные; эталон — прогон, посчитанный руками на 5 сделках |
| M9 | CLI и Docker | Запустить всё одной командой на своей машине | `discover`, `record`, `replay`, `run`, `report`, `journal verify`, `kill`; `docker run` работает с теми же командами; README проверен человеком, впервые видящим проект |

### Важное (после v0.1, при наличии времени в 10 активных дней)
| № | Функция | Критерий |
|---|---|---|
| I1 | Панель | FastAPI + одна HTML-страница: позиции, экспозиция, хвост журнала, кнопка kill; состояния пусто/загрузка/ошибка/офлайн |
| I2 | Внешняя справедливая цена | Публичный WebSocket Binance для BTC/ETH спота как вход наклона; отдельный модуль, отключаемый |
| I3 | Перебор параметров | `paperfill sweep` по сетке параметров стратегии на реплее с таблицей результатов |

### Желаемое
Адаптер Kalshi; экспорт метрик Prometheus; блокнот с разбором прогона.

### Не делаем
- **Live-исполнитель.** Ни в v0.1, ни позже без отдельного решения владельца и
  юриста (`docs/decisions/0001`). Интерфейс исполнителя имеет одну реализацию.
- Кошельки, ключи, подпись ордеров, pUSD.
- Накрутка объёма, wash trading, спуфинг — запрещены условиями Polymarket.
- Обход географических ограничений.
- Рынки neg-risk и многоисходные: вне объёма v0.1, пропускаются с записью в журнал.
- Windows.

## 3. Нефункциональные требования
- Деньги и цены — `Decimal`, никаких float в расчётах (`python/decimal-module.md`).
- Лимиты API: уважать `429`/`Retry-After`; настраиваемый потолок запросов в секунду.
- Детерминизм: один вход → один журнал с тем же итоговым hash.
- Память ≤ 300 МБ на реплее рынка в 10 000 сделок; время реплея не важно.
- Личных данных нет: адреса кошельков из ленты сделок не сохраняются в журнал
  (только цена, размер, сторона, время).
- Воспроизводимость: `uv.lock`, CI на 3.11 и 3.14, Docker из lock-файла.
- Покрытие тестами: порог назначается после M4, не ниже фактического минус 5 п.п.

## 4. Краевые случаи и ошибки
- Рынок разрешился во время прогона: позиции закрываются по 1/0, запись в журнал.
- Обрыв WebSocket: событие `gap`, переподключение, стакан перечитывается REST.
- `429` от Data API: ожидание `Retry-After`, запись в журнал, без потери страницы.
- Частичное исполнение и остаток ордера; отмена ордера с частичным исполнением.
- Пустой стакан; стакан только с одной стороной.
- Комиссия ноль (`feesEnabled=false` или геополитика).
- `accepting_orders=false`, `closed=true` — ордера отклоняются с причиной.
- Изменение тика: событие `tick_size_change` со старым и новым тиком (polymarket/realtime-data.md, пример 0.01 → 0.001); симуляция обязана перечитать тик из события.
- Расхождение часов: все времена UTC, источник — сервер, локальное время только для журнала получения.

## 5. Состояния интерфейса (панель, I1)
Пусто (нет прогона), загрузка, ошибка (API недоступен), частичные данные
(есть журнал, нет стакана), офлайн (WebSocket в `gap`).

## 6. Локализация и форматы
Интерфейс и README — английский. Время — ISO 8601 UTC. Деньги — USDC с 6 знаками,
комиссии с 5 знаками (`polymarket/fees.md`). Один язык, без переключателя.

## 7. Лицо продукта
Имя `paperfill`, справка `paperfill --help`, README с разделом «What this is not»
до инструкции по установке, заголовок панели. Входит в объём M9/I1.

## 8. Срок
Критерий: объём M1–M9 помещается в 10 активных дней без урезания планки.
Не помещается — режем функции (сначала I-блок, затем M6 упрощается до
одностороннего котирования), не качество.
